# MOECISH 審查啟發清單(Review Heuristics / Walkthrough Checklist)

> **用途**:把 UAT 重測累積的「人味」回饋沉澱成可重複套用的審查規則。
> 純讀 code 的審查抓得到結構/資安/一致性錯誤,卻常漏掉「流程合不合理、文案會不會誤導、這個角色此刻到底有沒有事做」這類領域判斷——而這正是手動重測一直在撈的那類。
> **怎麼用**:每批改動前後,對照本清單逐條自問;能自動化的已連到測試(見「覆蓋」欄),其餘標 👤=需人工/Chrome MCP 擬人走查。
> 新學到的規則一律加進本檔(連同出處批次),讓下一輪自動套。

**覆蓋圖例**:✅ 自動測試鎖定 ・ 🔶 半自動(可 grep/掃描比對) ・ 👤 目前只能人工/擬人走查

相關 SoT:[ACCESS-MATRIX.md](ACCESS-MATRIX.md)(角色×階段真值表)、[QA-WALKTHROUGH.md](QA-WALKTHROUGH.md)(逐角色逐階段步驟)、記憶 `moecish-copy-conventions`(全站用詞 SoT)。

## 套用方式(每批)
1. **改動前**:挑出本批觸及的類別(通知?文案?角色×階段?),逐條看相關規則。
2. **改動後**:跑 `test:access` + `test:isolation`(+ `test:notify`);對 🔶 項做對應 grep;對 👤 項用 Chrome MCP 以該角色實機走一遍。
3. **新回饋**:把每個「我漏掉、使用者撈到」的問題抽象成一條規則加進本檔(註明批次),儘量再往 ✅/🔶 推。
